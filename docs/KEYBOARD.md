# Экранная клавиатура для приложений

Ветка `codex/external-keyboard`, 2026-09-08. Реализован ручной ввод в локальные
Chromium (Браузер и YouTube) и Kodi. Код и транспорт X11 проверены автоматически;
2026-09-09 пользователь подтвердил работу после ручной проверки.

## Использование

1. В приложении выбери поле текста: тачпадом или навигацией по элементам.
2. Нажми **Options → Клавиатура**. При вызове меню сохраняются приложение и окно,
   которым принадлежал фокус. Из главного экрана этот пункт недоступен.
3. Набери текст. Доступны **ABC/АБВ**, **Aa**, **123 #**, пробел, удаление,
   стрелки для перемещения курсора в черновике и **Очистить**.
4. **Вставить** передаёт текст без подтверждения формы. **Вставить и Enter**
   дополнительно нажимает Enter. Нажатие Enter физической клавиатуры в черновике
   действует как «Вставить».
5. **O / Отмена / Options** закрывает редактор без отправки и возвращает быстрое
   меню. Ещё одно O возвращает приложение. **PS** очищает черновик и открывает Home.

**Скрыть текст** маскирует черновик для ввода в парольное поле. Режим отображения
не определяет тип поля в приложении: его нужно выбрать до вызова Options.
Черновик очищается после отправки, отмены, выхода Home или отключения контроллера.
Для первой проверки парольного поля используй выдуманный пароль.

Отправка ограничена 512 печатными символами за раз. Переносы строк и Tab в тексте
не принимаются; Enter передаётся только отдельной командой. Уже находящийся в поле
текст не считывается: клавиши редактора исправляют черновик, а вставка происходит
в текущую позицию или вместо выделения в приложении.

## Границы реализации

- Автоматического появления при фокусе поля пока нет. Moonlight и удалённый ввод
  этим этапом не охвачены.
- Закрепляется X11-окно и его дочернее окно ввода. Отдельный DOM-элемент сайта
  или виджет Kodi не идентифицируется: страница может сама переместить курсор
  внутри своего окна. Перед вызовом клавиатуры поле должно быть выбрано.
- При закрытии приложения, смене окна или отмене отправка прекращается.
  Частично введённый текст не откатывается и не отправляется повторно автоматически.
  После ошибки проверь поле и заново открой Options → Клавиатура.
- Во время быстрого меню, меню питания и отправки текста evdev временно захватывает
  кнопки геймпадов. После возврата приложению устройства освобождаются; при
  отключении контроллера и выходе оболочки захват также снимается. Пользователь
  подтвердил работу после передачи ему списка ручных проверок, включая Kodi.

## Транспорт и данные

Одноразовый процесс `raspberry_tv.text_input` получает текст через stdin. Текст не
передаётся в аргументах процесса, не попадает в настройки и журналы лаунчера и не
помещается в буфер обмена. Это не управляет историей или сохранением данных самим
целевым приложением.

Используется [XTEST](https://www.x.org/releases/X11R7.5/doc/Xext/xtestlib.html).
Для символов временно назначается свободная клавиша X11, затем её исходное назначение
восстанавливается. Проверка фокуса и пара нажатие/отпускание выполняются между
[`XGrabServer` и `XUngrabServer`](https://www.x.org/releases/current/doc/libX11/libX11/libX11.html#Controlling_the_Server),
чтобы запрос другого клиента не сменил фокус между проверкой и отправкой.
Между символами сервер освобождён. Отмена завершает вспомогательный процесс;
обработчик SIGTERM восстанавливает назначение клавиши.

## Автоматические проверки

Без окон и действий через интерфейс лаунчера:

```bash
python3 -m unittest tests.test_core tests.test_processes tests.test_pi_integration tests.test_bluetooth tests.test_zapret tests.test_bridge tests.test_text_input -v
```

На Pi прошли 64 проверки. На Windows — 62 успешных и 2 пропуска Linux-проверок.
QML скомпилирован без создания окна. `tests.test_ui` в этом этапе не запускались:
по договорённости все действия через интерфейс выполняет пользователь.

Ещё 4 проверки транспорта прошли на отдельном Xvfb: латиница/кириллица/символы,
явный Enter, потеря фокуса, отмена с восстановлением раскладки и отпусканием клавиши.
Они проверяют события X11, а не поведение виджетов Chromium/Kodi.
Для воспроизведения нужен Xvfb; телевизионный DISPLAY не используется:

```bash
RASPBERRY_TV_X11_TESTS=1 python3 -m unittest tests.test_text_x11 -v
```

Если Xvfb распакован отдельно, его путь задаётся переменной `RASPBERRY_TV_XVFB`.

## Ручная приёмка

Сначала установи сборку этой ветки по [INSTALL.md](INSTALL.md). Для локальной
страницы проверки из корня репозитория можно запустить:

```bash
python3 -m http.server 8840 --bind 127.0.0.1 --directory docs
```

Открой в браузере Pi `http://127.0.0.1:8840/keyboard-test.html`. На странице нет
отправки формы на сервер и сохранения полей. **2026-09-09 пользователь сообщил,
что всё работает.** Ниже сохранён чек-лист для повторных прогонов.

- В первом поле через Options → Клавиатура набрать `Привет TV 123!` и нажать
  **Вставить**. Строка точная, счётчик подтверждений остаётся 0.
- Во втором поле набрать другую строку и выбрать **Вставить и Enter**.
  Первое поле не меняется, счётчик увеличивается ровно на 1.
- Проверить ABC/АБВ, Aa, 123 #, пробел, удаление, стрелки курсора и очистку.
  Все кнопки видны при 720p и доступны крестовиной/стиком без мыши.
- В тестовом парольном поле использовать выдуманную строку. **Скрыть текст**
  маскирует черновик; после вставки поле сайта также показывает маску.
- Закрыть черновик через O, Options и PS. Ничего не вставляется; после нового
  вызова черновик пуст. Возврат в приложение восстанавливает управление и тачпад.
- Набрать достаточно длинную строку, отправить и во время ввода нажать PS.
  Отправка прекращается, открывается Home; после возврата нет продолжающегося ввода.
- В плитке YouTube выбрать поиск, ввести русский запрос и подтвердить.
  Проверить также ввод в обычное поле другого сайта через плитку Браузер.
- В Kodi открыть поиск и повторить ввод. Навигация по клавиатуре не должна
  одновременно двигать выбор или нажимать кнопки в Kodi под ней.
- Повторить короткий ввод по USB и Bluetooth. Отключить контроллер при открытом
  черновике и подключить снова: старого текста нет, управление возвращается.
- Проверить прежний **Открыть адрес**, редактор стартовой страницы без сохранения,
  меню питания и возврат Home — общая клавиатура и меню не должны регрессировать.

Для отчёта достаточно номеров/названий неудачных пунктов, приложения и того,
что произошло вместо ожидаемого. Сбор журналов лаунчера выполняет разработчик;
введённый пароль присылать не нужно.
