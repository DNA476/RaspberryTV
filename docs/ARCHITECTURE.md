# Архитектура 0.1

## Целевая система

Raspberry Pi OS Lite 64-bit, Trixie, Raspberry Pi 5. Сборка носителя `2026-06-18`, pi-gen `stage2`. 5 сентября 2026 система установлена и проверена по SSH: Debian 13.5, aarch64; оболочка выведена на телевизор через HDMI-2.

[Официальный список образов Raspberry Pi](https://www.raspberrypi.com/software/operating-systems/) соответствует этой версии. [PySide6 Qt Quick для Debian Trixie](https://packages.debian.org/trixie/python3-pyside6.qtquick) доступен для arm64. На Pi проверены отрисовка и базовые переходы на системном Qt 6.8.2; локальный предпросмотр проверяется на Qt 6.11.2.

## Слои

```text
LightDM → X11 / Openbox → пользовательский systemd → Qt Quick
                                                     ↕
                                            Bridge / очередь задач
                                             ↙       ↓       ↘
                                         Settings  LinuxSystem Applications
                                                     ↑
                                        evdev / глобальные кнопки
```

- `qml/`: интерфейс, геометричные значки, фокус, модальные панели и экранная клавиатура. Из интерфейса нельзя передать произвольную shell-команду.
- `bridge.py`: допустимые действия и состояние интерфейса. Долгие операции выполняются последовательно в отдельном потоке; изменения Qt-состояния возвращаются через сигналы.
- `config.py`: проверка настроек, нормализация доменов, запись через временный файл и `os.replace`, резервная копия последнего состояния. На Linux синхронизируются файл и каталог.
- `processes.py`: фиксированные команды приложений, собственные процессы и их окна. Управление процессами не использует shell или `killall`.
- `linux.py`: NetworkManager (`nmcli`), Bluetooth (`bluetoothctl`), KDE Connect, XRandR. Эти адаптеры не запускаются в режиме предпросмотра.
- `display_guard.py`: отдельный процесс отката режима экрана. В отсутствие подтверждения или при закрытии канала родителя возвращает прежние разрешение и частоту. После перезагрузки новый режим не применяется автоматически.
- `input.py`: чтение evdev без эксклюзивного захвата устройства, короткое/длинное PS, Options, повтор стрелок и мёртвая зона стика.
- `deploy/`, `scripts/`: отдельный сеанс X11, автозапуск, ограниченное правило polkit для изменения сети активным TV-пользователем, восстановление по SSH.

## Почему X11

Для первого установочного профиля используются Openbox, wmctrl и xdotool. Это позволяет управлять окнами Kodi, Chromium и Moonlight, выводить Qt-панель поверх приложения и возвращать фокус глобальной кнопкой. В сессии нет панели, файлового менеджера и меню рабочего стола.

Это рабочее инженерное допущение, а не подтверждение производительности видео: аппаратное декодирование, OpenGL, режимы HDMI и задержку Moonlight нужно измерить на Pi. [Документация Openbox](https://manpages.debian.org/trixie/openbox/openbox.1.en.html).

## Запуск и возврат

При запуске приложения оболочка показывает индикатор до появления окна. Приложения отслеживаются по собственному PID и дереву потомков. Для окон без `_NET_WM_PID`, как у установленного Kodi, владелец определяется через [XRes в python-xlib](https://github.com/python-xlib/python-xlib/blob/master/examples/xres.py). Совпадение заголовка окна не используется как доказательство принадлежности.

Главное окно скрывается, а при вызове быстрого меню снова открывается как прозрачное окно поверх приложения. Композицию выполняет [Picom](https://manpages.debian.org/trixie/picom/picom.1.en.html), backend XRender, без теней и анимаций. Правило для Qt-оболочки сохраняет композицию поверх полноэкранного Kodi. F1/F2/F3 из Openbox обращаются к запущенному экземпляру через локальный сокет с доступом только текущего пользователя.

Xorg получает VC4 как PrimaryGPU через [OutputClass](https://manpages.debian.org/trixie/xserver-xorg-core/xorg.conf.5.en.html): Pi 5 также предоставляет V3D-устройство, которое нельзя выбирать основным контроллером дисплея. При подключении телевизора без активного режима оболочка включает предпочитаемый режим XRandR. `kodi.py` отключает команды standby/inactive source при выходе Kodi, сохраняя предыдущий XML в резервной копии.

Обработка Options не захватывает устройство эксклюзивно: приложение также может увидеть кнопку. Конкретные конфликты и раскладка будут проверяться с DualSense на Pi. Тачпад пока предполагает штатную обработку драйвером/libinput; собственной эмуляции курсора нет.

## Состояние zapret

Интеграция установлена и проверена на Pi. `zapret.py` — непривилегированный
клиент Unix socket; `zapret_service.py` — отдельная root-служба с фиксированными
операциями. Код и активное состояние принадлежат root, socket доступен группе
`raspberry-tv`. GUI передаёт проверяемые значения, а не команды и пути.

Используется неизменённый разбор стратегий Linux-адаптера
[Sergeydigl3](https://github.com/Sergeydigl3/zapret-discord-youtube-linux/tree/69db771b527ba11ca71efe28728a7f9491eec352).
Версии адаптера, стратегий Flowseal и nfqws закреплены вместе с SHA-256 архивов.
Служба запускает собственный foreground-процесс nfqws, который переходит к
пользователю `nobody`; глобальный `pkill -f nfqws` upstream не вызывается.

Сетевые правила используют собственную таблицу `inet raspberry_tv_zapret`
и NFQUEUE 221 с `bypass`. Перед очередью исключаются локальные адреса, SSH 22
и стандартные порты Sunshine. Положительные hostlist/ipset исходных стратегий
заменяются доменами GUI, сохраняя параметры DPI и исключения. GameFilter
расширяет порты, но не снимает ограничение по доменам.

Перед применением служба атомарно сохраняет состояние для отката. Без
подтверждения за 60 секунд возвращаются прежние настройки; перезапуск во время
пробного изменения также восстанавливает их. Подтверждённый профиль сохраняется.
Подбор последовательно запускает стратегии и делает ограниченные по времени
HTTPS-проверки, затем возвращает исходное состояние. Из результатов выбирается
черновик для отдельного применения. Доступность страницы не равна проверке видео.

Установка, границы обработки и аппаратные проверки описаны в [ZAPRET.md](ZAPRET.md).

## Границы проверки

Codebase Memory используется для поиска символов и трассировки. Индекс на Windows иногда сообщает `metadata_changed` уже после автоматического обновления, а каталог `deploy` исключён индексатором. Для этих файлов источником истины являются прямое чтение и профильные проверки; отсутствие пробелов в графе не считается доказательством полноты.
