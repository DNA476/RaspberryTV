# Установка Raspberry TV

Инструкция для **Raspberry Pi 5 и Raspberry Pi OS Lite 64-bit на Debian 13 Trixie**.
На этой системе проверены оболочка, Kodi, DualSense по USB/Bluetooth и YouTube
с видео и звуком через zapret. Другие платы, 32-bit OS и другие выпуски Debian
установщик оболочки отклоняет. Это исходники и установочные скрипты, готового
образа `.img` в репозитории нет.

## 1. Подготовь Pi

Нужны Pi 5, подходящее питание, носитель с ОС, телевизор и micro-HDMI → HDMI,
подключение к интернету. Для первого запуска удобна USB-клавиатура; затем можно
подключить DualSense. Клавиатура в сторонних приложениях пока отдельная задача
из [плана развития](ROADMAP.md).

Если ОС уже установлена, этот шаг можно пропустить. На компьютере открой
[Raspberry Pi Imager](https://www.raspberrypi.com/software/), выбери Pi 5 и
Raspberry Pi OS Lite **64-bit**. В настройках образа задай имя устройства,
обычного пользователя, пароль, Wi-Fi/страну (если нужен Wi-Fi) и включи SSH.
Для SSH можно использовать собственный публичный ключ. Проверь выбранный
носитель перед записью: запись образа удаляет его прежнее содержимое.
Подробнее — [официальная инструкция Raspberry Pi](https://www.raspberrypi.com/documentation/computers/getting-started.html).

Вставь носитель в Pi, подключи телевизор и сеть, включи питание. Дальнейшие
Linux-команды выполняются **на работающей Pi**, через SSH или её консоль,
а не на компьютере с подключённой флешкой.

Например, если при записи выбраны пользователь `tvuser` и имя `raspberrytv`:

```bash
ssh tvuser@raspberrytv.local
```

Подставь свои имена. Если `.local` не находится, используй IP Pi из списка
устройств роутера. Пароли и приватные SSH-ключи в репозиторий не добавляй.

Проверь систему:

```bash
cat /etc/os-release
dpkg --print-architecture
tr -d '\0' </proc/device-tree/model
```

Ожидаются `VERSION_CODENAME=trixie`, `arm64` и `Raspberry Pi 5`. Не выбирай
образ только по слову «последний»: следующий выпуск ОС может требовать адаптации.

## 2. Скачай исходники

В SSH-сеансе **обычного пользователя Pi**:

```bash
sudo apt-get update
sudo apt-get install -y git ca-certificates
cd ~
git clone https://github.com/DNA476/RaspberryTV.git
cd RaspberryTV
```

GitHub-аккаунт для чтения публичного репозитория не нужен. На Pi используется
системный Python/Qt из APT; создавать `.venv` или ставить PySide6 через pip для
TV-сеанса не требуется.

## 3. Установи оболочку и включи TV-сеанс

Сначала проверь совместимость и план установки пакетов:

```bash
bash scripts/install-pi.sh --user "$USER" --check
```

Это симуляция APT: пакеты не устанавливаются. Затем выполни:

```bash
sudo bash scripts/install-pi.sh --user "$USER" --enable-session
```

Здесь `$USER` — твой обычный пользователь Pi. Не выполняй команды из root-shell:
установщик намеренно запрещает автологин под root. Дождись завершения APT и скрипта.
Если нужен только перенос файлов без включения автологина, опусти `--enable-session`.

Скрипт устанавливает системный Qt, X11, LightDM, Openbox, Picom, Kodi, Chromium,
PipeWire, компоненты Bluetooth/NetworkManager/KDE Connect и средства управления
окнами. Исходники копируются в `/opt/raspberry-tv`, настройки сеанса — в `/etc`.
Создаётся группа `raspberry-tv`; в неё добавляется TV-пользователь. Режим экрана
обслуживает X11, Wayland этим профилем не поддерживается.

При `--enable-session` после загрузки будет автоматически открыт сеанс Raspberry TV
под выбранным пользователем. Это настройка для отдельной приставки: любой с доступом
к устройству получит её TV-сеанс. Установщик сам не перезагружает Pi.

```bash
sudo reboot
```

SSH-соединение завершится. В текущем коде главный экран содержит пять
плиток: **Kodi, YouTube, Moonlight, Браузер, Настройки** (в первой версии 0.1.0 — четыре).
Браузер и диалоги питания проверены на Pi; ручная приёмка описана в [STATUS.md](STATUS.md).
Повторно подключись по SSH, когда
понадобятся следующие шаги. Перезагрузка также применяет новое членство в группе.

## 4. Подключи DualSense

Дополнительные кнопки, щелчки по половинам тачпада и направление прокрутки описаны
в [DUALSENSE.md](DUALSENSE.md). Установщик настраивает `uinput`; доступ выдаётся
активному пользователю сеанса, поэтому после установки нужно войти в TV-сеанс.

Для проверки по кабелю подключи DualSense к USB Pi. Для Bluetooth:

1. Открой **Настройки → Устройства → Добавить Bluetooth-устройство**.
2. На контроллере удерживай **PS + Create**, пока подсветка не начнёт мигать.
3. Выбери контроллер в списке и дождись завершения сопряжения.
4. Проверь кнопки, стики и тачпад; для проверки Bluetooth отсоедини USB-кабель.

Сообщение «Подключено» выдаётся после проверки сопряжения и готовности ввода.
После сопряжения для повторного подключения нажми PS. Если контроллер уже
подключён к другому устройству, сначала отключи его там.

| Действие | DualSense | Клавиатура |
| --- | --- | --- |
| Навигация | Крестовина / левый стик | Стрелки |
| Выбрать | X | Enter / пробел |
| Назад | O | Esc |
| На главный экран | Короткое PS | F1 |
| Быстрое меню | Options | F2 |
| Меню питания | Удержание PS | F3 |

Тачпад использует штатный Linux-ввод. В ветке `codex/external-keyboard` клавиатура
обслуживает также поля браузера, YouTube и Kodi: выбери поле → **Options → Клавиатура**
→ набери текст → **Вставить** или **Вставить и Enter**. Автоматического появления пока
нет, Moonlight не поддерживается. Работа подтверждена пользователем; инструкция и
чек-лист повторной проверки — в [KEYBOARD.md](KEYBOARD.md).

### Браузер и меню питания

Плитка **Браузер** запускает полноэкранный Chromium с собственным профилем.
По умолчанию открывается `https://www.google.com/`; изменить адрес можно через
**Настройки → Система → Стартовая страница браузера**. Старые настройки автоматически
получают это значение, сетевые параметры при этом сохраняются.

В браузере **Options → Открыть адрес** показывает клавиатуру оболочки. Введи адрес
и выбери **Открыть** — сайт появится в новой вкладке существующего окна.
Без схемы добавляется `https://`; локальные HTTP-сайты указывай
с `http://`. Домены на кириллице поддерживаются. При ошибке поле остаётся открытым
для исправления. Произвольный поисковый запрос здесь пока не поддерживается.

В быстром меню доступны история назад/вперёд и обновление страницы.
Влево/вправо на геймпаде переключают элементы страницы, вверх/вниз прокручивают,
X активирует элемент; O передаёт Escape. История назад вызывается отдельным пунктом
меню. Тачпад также можно использовать для указателя. Короткое PS возвращает
в оболочку; повторное нажатие плитки возвращает уже открытое окно браузера.

YouTube сохраняет отдельный профиль и kiosk-режим. Для поисковых и парольных полей
используется отдельный пункт **Клавиатура**, описанный выше.

Значок питания в правом верхнем углу открывает то же меню, что F3/удержание PS.
Выключение и перезагрузка требуют подтверждения; отмена возвращает фокус.
**Спящий режим недоступен**, пока не проверены поддержка и пробуждение на Pi.
Результаты проверки и оставшиеся пункты приёмки — в [STATUS.md](STATUS.md).

## 5. Установи zapret, если он нужен в твоей сети

Это отдельный системный компонент. В нём закреплены версии Linux-адаптера,
стратегий и ARM64 nfqws, а SHA-256 исходных архивов проверяются перед упаковкой.
Описание границ обработки и источников — в [ZAPRET.md](ZAPRET.md).

После повторного подключения по SSH:

```bash
cd ~/RaspberryTV
python3 scripts/prepare-zapret.py
```

Подготовка выполняется **без sudo**, предпочтительно на Pi. Она скачивает архивы
из GitHub и создаёт `.run/zapret-assets/raspberry-tv-zapret-assets.tar.gz`.
Нужен доступ к GitHub/codeload; при ошибке скачивания или несовпадении контрольной
суммы не переходи к установке. На Windows общий архив release может вызвать
срабатывание Defender; детали фактического наблюдения записаны в [ZAPRET.md](ZAPRET.md).

Проверь реальные ARM-стратегии без применения сетевых правил:

```bash
mkdir -p .run/zapret-check
tar -xzf .run/zapret-assets/raspberry-tv-zapret-assets.tar.gz -C .run/zapret-check
python3 scripts/check-zapret.py .run/zapret-check
bash scripts/install-zapret-pi.sh --check
```

Для закреплённого набора ожидается **88 dry runs, 0 failures**: 22 стратегии и
четыре сочетания GameFilter. Этот тест проверяет параметры, а не обход блокировок.
Установи службу и обнови работающую оболочку:

```bash
sudo bash scripts/install-zapret-pi.sh .run/zapret-assets/raspberry-tv-zapret-assets.tar.gz
systemctl --user restart raspberry-tv.service
systemctl is-active raspberry-tv-zapret.service
```

Последняя команда должна вывести `active`: управляющая служба готова.
**При первой установке обработка трафика выключена**, даже когда сама служба active.
Инсталлятор также обновляет код оболочки из текущего checkout; её перезапуск закрывает
запущенные ею приложения, поэтому сначала закончи просмотр.

На телевизоре открой **Настройки → Сетевые правила**:

1. Выбери профиль **YouTube** и проверь домены.
2. Выбери фактический интерфейс: обычно `wlan0` для Wi-Fi или `eth0` для кабеля.
3. Выбери стратегию. На проверенной Pi сработала `general (ALT).bat`; для другого
   провайдера результат может отличаться. GameFilter TCP/UDP для начала оставь выключенными.
4. Выбери **Применить и включить** и подтверди изменение сети.
5. Проверь соединение. За 60 секунд вернись в этот раздел и выбери **Оставить изменения**.
   Без подтверждения служба автоматически восстановит прежние правила.

Подтверждённый профиль сохраняется и запускается при загрузке. Кнопка
**Откатить изменение** возвращает предыдущее состояние. SSH 22, локальные адреса
и стандартные порты Moonlight исключены из обработки.

Если стратегия не подошла, используй **Подобрать стратегию**. Для подбора задай
до 10 хостов с работающим HTTPS, например `www.youtube.com` и `i.ytimg.com`.
Корневые CDN-домены могут не иметь DNS-записи или страницы. После проверки служба
вернёт прежний профиль, а результаты позволят выбрать стратегию в черновик.
Перед окончательным применением верни профиль YouTube, чтобы включить `googlevideo.com`
и его поддомены для самого видео. Успех HTTPS-проверки ещё не подтверждает потоковое
воспроизведение — отдельно запусти ролик с телевизора.

## 6. Что готово после установки

Kodi и Chromium устанавливаются основным скриптом. YouTube запускается через
Chromium в kiosk-режиме с отдельным профилем и включённой песочницей. Перед запуском
Kodi оболочка отключает его команды выключения телевизора при выходе и сохраняет
исходный XML рядом с суффиксом `.before-raspberry-tv`.

**Moonlight пока не устанавливается**: плитка и команда запуска подготовлены,
но установка клиента и сопряжение с Sunshine ещё не завершены. HDMI-CEC-пульт,
автоматический вызов клавиатуры и спящий режим также не готовы. Проверка браузера описана в [STATUS.md](STATUS.md).
Полное состояние — [STATUS.md](STATUS.md), будущие изменения — [ROADMAP.md](ROADMAP.md).

## 7. Диагностика и восстановление

### Оболочка не появилась / чёрный экран

Проверь питание, micro-HDMI, выбранный вход телевизора. Затем по SSH:

```bash
systemctl status lightdm.service --no-pager
systemctl --user status raspberry-tv.service --no-pager
tail -n 100 ~/.config/raspberry-tv/launcher.log
sudo journalctl -u lightdm.service -b -n 100 --no-pager
```

Пользовательский `journalctl --user -u raspberry-tv.service` доступен не на каждой
конфигурации journal; файл `launcher.log` — дополнительный источник диагностики.
Если `systemctl --user` не видит bus, подключись по SSH под тем же TV-пользователем
и убедись, что его сеанс запущен; не подменяй команду вызовом `sudo systemctl --user`.

Чтобы отключить автологин и вернуться к консольной загрузке:

```bash
sudo raspberry-tv-recovery
```

Команда останавливает графический сеанс и меняет цель следующей загрузки, но не
удаляет сеть и данные приложений. После исправления повтори установку оболочки
с `--enable-session` и перезагрузи Pi.

### Проблема с сетью после изменения zapret

Дождись автоматического отката неподтверждённого изменения. Для немедленной остановки:

```bash
sudo systemctl stop raspberry-tv-zapret.service
journalctl -u raspberry-tv-zapret.service -b -n 100 --no-pager
```

Остановка удаляет только таблицу `inet raspberry_tv_zapret`. Чтобы не запускать
службу при следующей загрузке, используй `sudo systemctl disable --now raspberry-tv-zapret.service`.
Обратное действие: `sudo systemctl enable --now raspberry-tv-zapret.service` — оно
восстанавливает сохранённое состояние обработки, поэтому учитывай последний профиль.

### Где находятся данные

| Путь на Pi | Содержимое |
| --- | --- |
| `/opt/raspberry-tv` | Установленный код оболочки и адаптера |
| `/etc/raspberry-tv` | Настройки Openbox и Picom |
| `~/.config/raspberry-tv/settings.json` | Настройки GUI и черновик zapret |
| `~/.config/raspberry-tv/settings.backup.json` | Предыдущие настройки GUI |
| `~/.config/raspberry-tv/launcher.log` | Журнал оболочки |
| `/opt/raspberry-tv-zapret` | Закреплённые upstream-компоненты |
| `/var/lib/raspberry-tv-zapret/state.json` | Активные правила и состояние отката; запись только root |

Сброс настроек оболочки не является заводским сбросом и не отключает отдельно
установленные сетевые службы.

## 8. Обновление исходников

Автоматического обновления оболочки из GUI пока нет. Перед обновлением закончи
просмотр и сохрани нужные данные приложений. Сам `git pull` не меняет код в `/opt`.

```bash
cd ~/RaspberryTV
git pull --ff-only
bash scripts/install-pi.sh --user "$USER" --check
sudo bash scripts/install-pi.sh --user "$USER" --enable-session
```

Если используется zapret, повтори подготовку пакета, проверку стратегий и его установку
из раздела 5. После обновления перечитай пользовательскую службу и перезапусти оболочку:

```bash
systemctl --user daemon-reload
systemctl --user restart raspberry-tv.service
```

Читай изменения перед обновлением:
автоматического отката версии приложения пока нет. Инсталлятор zapret сохраняет
предыдущие upstream-файлы в `/opt/raspberry-tv-zapret-backup.*`, а откат сетевых
параметров управляется отдельно через GUI.
